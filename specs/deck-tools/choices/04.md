# Slice 04 choices

- **Thresholds kept at the spec's 15% / 20 decks**, exposed as `--gem-max` and `--gem-min-decks`.
  Alternative: a cap relative to the commander's deck count. Why: on Zedruu (12,637 decks) and Zur
  (17,432) the top gems by lift sit at 5–15% and hundreds of decks, so 20 only bites on small
  commanders, which is its job; a fixed % reads plainer.
- **`--gems` prints only the gems section and exits** (like `--themes`). Alternative: append it to the
  normal report. Why: the normal report is already long; gems is a separate question.
- **Basics are always excluded**, deck cards only with `--deck`. Why: a basic is never a gem.
- **Column layout**: `lift`, `inc`, `trend` (signed z-score), name, as in the spec's example; `--top` rows.
- **`exclude` matches case-insensitively and by front face** (`scores._keys`), the same matching the
  existing `--deck` comparison uses.
- **Fixture trimmed from the live Zur page** (5 lists, 19 cards, only the fields `_cards` reads).
  `min_decks` is tested with a raised threshold (2000) because no real Zur card is under 20 decks.
